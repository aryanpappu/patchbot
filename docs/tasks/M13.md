## Deliver `internal/server` and `patchbot serve`
- `patchbot serve [--addr 127.0.0.1:8080]`. Refuse any non-loopback address unless `PATCHBOT_UI_TOKEN` is set.
  When the token is set, require it as a bearer token (constant-time compare) on every request.
  Never log or echo it.
- JSON API exactly as in PLAN.md section 7:
  - `GET /api/providers`, `GET /api/providers/{id}/models` (live list merged with config, with the warning
    when live listing fails)
  - `GET /api/runs` (filters plus cursor pagination), `POST /api/runs`
  - `GET /api/runs/{id}` (run, latest spec, spec versions, approvals, steps summary, artifacts metadata)
  - `PUT /api/runs/{id}/spec`, and `POST /api/runs/{id}/approve|revise|reject|cancel|retry`
  - `GET /api/runs/{id}/events` (SSE)
  - `GET /api/runs/{id}/artifacts/{name}` for the diff, test output and PR text. These are already
    redacted; serve them as `text/plain` with `nosniff`.
- Long work runs in background goroutines owned by a run manager inside the server. Start, Execute after
  approve, revise and retry all go through the runner. The manager:
  - limits concurrency (config, default 2)
  - holds a cancel func per run so `cancel` stops work promptly
  - waits for in-flight runs on graceful shutdown (SIGINT/SIGTERM), with a timeout
  - leaves runs to stale recovery when the process dies
  Closing the browser never cancels a run.
- Run `SyncWaiting` every 60 s while serving, plus expiry, with a ticker that stops on shutdown.
- SSE:
  - The event id is the per-run seq. Replay from SQLite after `Last-Event-ID`, or after the `?after=` query.
  - Then follow live through an in-process broadcaster fed after each committed event write. If the
    broadcaster drops, fall back to polling the store.
  - Send a heartbeat comment every 15 s, and close the stream when the run reaches a terminal status and
    all events are sent.
  - A slow client must never block the runner: use bounded buffers, and when a client lags,
    disconnect it so it resumes with `Last-Event-ID`.
- Security (PLAN.md 5.9):
  - Protect every non-GET request with `http.CrossOriginProtection` plus a Host check against the bound
    address.
  - Send CSP, `X-Content-Type-Options`, `Referrer-Policy` and `X-Frame-Options` headers.
  - Limit request bodies (e.g. 1 MiB) and use strict JSON decoding that rejects unknown fields.
  - Use a consistent error JSON shape `{"error":{"kind","message"}}`, with no stack traces and no raw
    upstream errors.
  - Only allowlisted repos can start runs. UI actions are recorded under the configured local approver
    name with channel `ui`.
- HTTP server timeouts: read-header, read, idle. No write timeout on the SSE route.

## Tests (no network, no live keys)
Use `httptest` with the fake provider, a fake GitHub and bare repos, as the runner tests do. Cover:
- each endpoint's happy path and errors
- start → awaiting_approval → approve via API → PR on fake GitHub
- spec edit voiding approval
- SSE replay plus `Last-Event-ID` reconnect giving no gaps or duplicates (the M13 acceptance test), heartbeat,
  and close at terminal
- a slow client not blocking event writes
- cross-origin POST rejected, wrong Host rejected
- non-loopback bind refused without a token, and bearer required with one
- body too large, unknown JSON field
- cancel through the API stopping a running run
- graceful shutdown
- secrets never appearing in any response (seed a fake token and grep responses)
