(wins), docs/planning/PLAN-fable.md sections 3.1, 3.2, 3.4/3.5 and 9.3, docs/planning/PLAN-codex.md section 3, and the

internal/llm/openai and register kind "openai" in internal/llm/providers. Do not commit. No network, no new dependencies:

Target the Chat Completions API (not the Responses API): assistant tool_calls with JSON-string arguments, tool messages with tool_call_id, system message role. ListModels via GET /models (OpenAI, OpenRouter, Ollama /v1/models, LM Studio, Groq). Base URL required, API key optional (Ollama/LM Studio need none). Fixtures: synthetic, one set per server family (openai, openrouter, ollama, groq) incl. the quirks.

Common rules: normalized types in and out; tool calls in provider order; never put the API key, URL query secrets or
request bodies in errors or logs (use llm.Error with WithCause and SafeText); map HTTP status to llm error kinds
(401/403 auth, 429 rate_limit with retry-after, 503/overloaded, 5xx unavailable, context-length 400 -> context_too_long,
else bad_request; body-read/transport failures unavailable, JSON decode malformed); usage nil when unknown; response body
cap 10 MB; ctx respected; injectable base URL and http.Client.

Golden tests on httptest (use the in-memory transport helper if one exists in the repo, else net.Pipe-based): request bodies
vs testdata/*.req.golden.json with an -update flag; synthetic responses in testdata/*.resp.json; testdata/README.md says
they are synthetic and which API docs/version they follow. Cover: text; one tool call; two calls in one turn then both
results; mixed text+tool call; empty tool result; malformed arguments; max tokens with partial call; refusal/blocked;
429 with retry delay; 5xx; 401; context too long; missing usage; body cut mid-stream; ListModels pagination.

Must pass: gofmt -l . empty, go vet ./..., golangci-lint run 0 issues, go test -race ./... (cache overrides under
/private/tmp if needed). Report: files, checks, decisions the plan did not cover, honest gaps.
