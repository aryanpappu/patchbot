# Task M14: web page (Go html/template + Vue 3 from a CDN, no build step)

Work only in this worktree (branch `m14-web`). Do not commit. Write everything from scratch.
Read first: `docs/PLAN.md` sections 2, 5 (rule 9) and 7, `internal/server` (the M13 JSON API and SSE) and
its README or report. The page talks only to that API. Add no new Go dependencies and no npm or build step.

## Deliver `internal/web` (embedded with `//go:embed`) served by `internal/server`
- Go html/template renders each page shell and puts the initial state in `<script type="application/json"
  id="state">`, escaped by the template. Vue 3 global production build:
  - load it from jsDelivr with an exact version and an SRI `integrity` hash plus `crossorigin`
  - mount on that state with `[[ ]]` delimiters
  - with `vue_src = "local"` in config, serve a vendored copy from the binary instead; add the config key,
    and leave the vendored file as a clearly named placeholder plus a `make vendor-vue` target that
    downloads and checks the SRI hash, because the sandbox has no network
  Update the CSP to allow exactly that script origin (or `'self'` in local mode) and nothing else. No inline
  event handlers. The app JS is its own embedded file served from `'self'`; the JSON state block is data.
- Screens (PLAN.md 7):
  1. **New run:** repo dropdown of allowed repos, issue number, mode, provider then model (live list with a
     typed-ID fallback and the warning when live listing failed), optional separate refine model, budget,
     dry-run.
  2. **Runs list:** status chips, an "awaiting approval" badge with a count, cost, PR link, filters, and
     cursor paging.
  3. **Run detail** (`/runs/{id}`):
     - phase timeline, live log over SSE with automatic resume via `Last-Event-ID`, and token and cost
       counters
     - spec panel: rendered markdown with an edit box, version history and a diff between versions
     - buttons Approve, Revise (notes), Reject, Cancel, and Retry (choose provider and model), each
       enabled only in the statuses where the API allows it, with clear error display
     - diff view, test output, PR link
- Safety: render all model, issue and test output as text. No `v-html` anywhere, and add a test that fails
  if `v-html` appears. Markdown rendering is done in Go with a tiny safe subset (headings, lists, checkboxes,
  code, emphasis, links with http/https only) that escapes everything else. Alternatively, show plain
  preformatted text; pick the safe one and document it. Every POST uses `fetch` with JSON and same-origin
  credentials, so it passes M13's CrossOriginProtection. When `PATCHBOT_UI_TOKEN` is required, the page asks
  for it once, keeps it in `sessionStorage` only, and sends it as a bearer header; it must not appear in URLs.
  Because EventSource cannot send headers, use fetch-based streaming for SSE in that case.
- Reloading any page keeps state: state lives on the server, and the page refetches.
- Accessible: labels, keyboard focus, visible status text (not color alone), and a layout that works at
  phone width.

## Tests
Go tests with `httptest`:
- each page renders, the state JSON is escaped (inject `</script>` and an XSS payload into an issue title)
- the CSP header matches the mode
- static assets are served with correct types and `nosniff`
- no `v-html`
- the SRI attribute is present and pinned
- the markdown subset escapes HTML and rejects `javascript:` links
- the token is never rendered into HTML
Keep JS small and readable. JS unit tests are not required.
